# Цех — учет складских остатков

Система учета продукции на нескольких складах и у торговых представителей: Android-приложение представителя, веб-панель администратора/руководителя и FastAPI backend с защищенным контуром обмена с 1С.

- отдельная аутентификация заголовком `X-Integration-Key`;

## Запуск backend

```bash
docker compose up
```

Контейнер backend автоматически выполняет `alembic upgrade head`, после чего запускает API.

После запуска доступны:

- API: `http://localhost:8000`;
- Swagger UI: `http://localhost:8000/docs`;
- проверка состояния: `http://localhost:8000/health`.

## Первый администратор

В новой базе один раз вызовите:

```http
POST /api/v1/auth/bootstrap
Content-Type: application/json

{
  "email": "admin@example.local",
  "password": "replace-with-strong-password",
  "full_name": "Администратор"
}
```

После создания первого пользователя bootstrap перестает принимать новые запросы.

Токен выдается маршрутом `POST /api/v1/auth/token`. Он использует стандартную OAuth2-форму: поле `username` содержит email, поле `password` — пароль. В Swagger UI можно авторизоваться кнопкой **Authorize**.

## Роли

- `admin` — управление справочниками, пользователями, ценами, учетными операциями и сторнированием;
- `manager` — просмотр складов, товаров, остатков, задолженности, журналов и отчетов;
- `representative` — просмотр складских остатков и цен, собственных остатков/задолженности/истории, регистрация собственных продаж и возвратов.

Сдача денег фиксируется администратором либо доверенным интеграционным контуром: представитель не может самостоятельно уменьшить свою задолженность.

## Основные API

### Справочники и пользователи

- `GET/POST /api/v1/warehouses`;
- `GET/POST /api/v1/representatives`;
- `PATCH /api/v1/representatives/{id}` — назначить, заменить или снять учетную запись;
- `GET/POST /api/v1/products`;
- `PATCH /api/v1/products/{id}`;
- `GET/POST /api/v1/users`.

### Остатки и задолженность

- `GET /api/v1/balances/warehouses`;
- `GET /api/v1/balances/representatives`;
- `GET /api/v1/representatives/{id}/debt`.

### Операции

- `POST /api/v1/operations/receipt`;
- `POST /api/v1/operations/issue-to-representative`;
- `POST /api/v1/operations/warehouse-transfer`;
- `POST /api/v1/operations/representative-return`;
- `POST /api/v1/operations/sale`;
- `POST /api/v1/operations/payment`.

### Документы и деньги

- `GET /api/v1/documents?limit=100` — товарный журнал для администратора и руководителя;
- `POST /api/v1/documents/{id}/cancel` — сторно товарного документа администратором;
- `GET /api/v1/my/documents` — собственная товарная история представителя;
- `GET /api/v1/my/money-postings` — собственная денежная история представителя;
- `GET /api/v1/money-postings` — денежный журнал администратора/руководителя;
- `POST /api/v1/money-postings/{id}/reverse` — сторно ошибочной сдачи денег администратором.

### Отчеты

- `GET /api/v1/reports/summary` — агрегаты и детализация по представителям; поддерживаются параметры периода.

### 1С

- `GET /api/v1/integration/1c/snapshot`;
- `GET /api/v1/integration/1c/documents`;
- `GET /api/v1/integration/1c/money-postings`;
- `POST /api/v1/integration/1c/operations/...` — учетные операции от 1С.

Для этих маршрутов нужен `X-Integration-Key`.

## Сторнирование

Исходный документ и его проводки не удаляются. При сторно документ получает статус `cancelled`, текущие складские/представительские остатки получают обратное движение, а для продажи создается компенсирующая денежная проводка `adjustment`.

Перед сторно backend проверяет будущие списания по текущему регистру. Если обратное движение привело бы к отрицательному остатку, операция отклоняется с `409`. Например, нельзя отменить приход 10 единиц, если 4 уже выданы представителю и на складе осталось только 6.

Повторное сторно уже отмененного документа идемпотентно: дополнительных движений не создается. Ошибочная сдача денег также сторнируется отдельной компенсирующей денежной проводкой без удаления исходной записи.

## Обновления в реальном времени

Защищенный WebSocket доступен по адресу:

```text
ws://localhost:8000/api/v1/ws/updates
```

Android-клиент передает HTTP-заголовок:

```text
Authorization: Bearer <access-token>
```

Сервер отправляет события:

- `state_changed` — изменились остатки и/или задолженность;
- `catalog_changed` — изменились данные товара или его цены;
- `connected` — соединение установлено;
- `pong` — ответ на текстовое сообщение `ping`.

Android использует WebSocket напрямую. Веб-панель пока использует периодическое обновление REST-данных.

## Как устроены остатки

Все движения записываются в журнал `stock_postings`. Дополнительно поддерживаются таблицы текущих остатков для складов и представителей. При списании PostgreSQL блокирует строку текущего остатка до конца транзакции, поэтому два параллельных запроса не могут одновременно списать один и тот же доступный товар.

Миграция `0002_current_balances` строит текущий регистр из существующих проводок. Миграция `0003_allow_zero_money_posting` разрешает нулевую денежную проводку для бесплатной/нулевой продажи при сохранении товарного документа.

## Офлайн-режим Android

Продажи и возвраты, не отправленные из-за отсутствия сети или временной ошибки сервера, сохраняются в локальную Room3-базу. WorkManager отправляет их после появления сети с исходным `external_id`. Сервер остается источником истины: локальные остатки и задолженность не меняются до подтверждения операции backend.

Постоянно отклоненные сервером операции помечаются как требующие проверки и не создают бесконечного цикла фоновых запросов.

## Локальный запуск backend без Docker

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -e .
alembic upgrade head
uvicorn app.main:app --reload
```

На Windows команда активации окружения: `.venv\\Scripts\\activate`.

Если переменная `CEH_DATABASE_URL` не задана, используется SQLite-файл `ceh_sklad.db`. Схема БД всегда должна применяться через Alembic.

## Запуск Android

Откройте каталог `android/` в Android Studio и запустите debug-сборку на эмуляторе. По умолчанию приложение обращается к локальному backend через `http://10.0.2.2:8000/`.

Подробности: `android/README.md`.

## Запуск веб-панели

После запуска backend:

```bash
cd admin-web
npm install
npm run dev
```

Панель будет доступна по адресу `http://localhost:5173`. Vite проксирует `/api` на локальный FastAPI backend.

Подробности: `admin-web/README.md`.
