# Цех — учет складских остатков

Система учета продукции на нескольких складах и у торговых представителей.

## Что уже работает

- несколько физических складов;
- виртуальный склад для каждого торгового представителя;
- текущие остатки в реальном времени;
- розничная и оптовая цена каждого товара;
- перемещение склад → склад;
- выдача товара склад → торговый представитель;
- возврат торговый представитель → склад;
- продажа товара представителем со списанием его остатка;
- учет задолженности представителя после продажи;
- сдача денежных средств с уменьшением задолженности;
- роли `representative`, `admin`, `manager`;
- Android-приложение торгового представителя;
- web-панель администратора и руководителя;
- WebSocket-обновление остатков;
- базовая подготовка данных и архитектуры к интеграции с 1С.

## Архитектура

Репозиторий организован как монорепозиторий:

- `backend/` — FastAPI, бизнес-логика, PostgreSQL, JWT, WebSocket;
- `android/` — Android-приложение на Kotlin + Jetpack Compose;
- `admin-web/` — панель управления React + TypeScript;
- `docs/` — архитектура, API и правила интеграции с 1С.

## Базовые принципы учета

Остатки не редактируются напрямую. Любое изменение фиксируется документом движения и проводками по товару. Списание выполняется внутри транзакции с блокировкой строки остатка, поэтому параллельные операции не могут незаметно списать один и тот же товар дважды.

Денежные операции торгового представителя ведутся отдельным регистром: продажа увеличивает задолженность перед компанией, сдача денег уменьшает ее.

## Быстрый запуск backend

Требуются Docker и Docker Compose.

```bash
cp .env.example .env
```

Перед первым запуском обязательно измените в `.env`:

- `JWT_SECRET` — длинная случайная строка;
- `BOOTSTRAP_ADMIN_PASSWORD` — пароль первого администратора.

Запуск:

```bash
docker compose up --build
```

После запуска:

- API: `http://localhost:8000`;
- Swagger: `http://localhost:8000/docs`;
- health-check: `http://localhost:8000/health`.

Первый администратор создается автоматически из `BOOTSTRAP_ADMIN_LOGIN` и `BOOTSTRAP_ADMIN_PASSWORD`.

## Запуск web-панели

```bash
cd admin-web
npm install
npm run dev
```

Откройте `http://localhost:5173` и войдите учетной записью администратора.

## Первичная настройка системы

После входа администратора рекомендуемый порядок такой:

1. создать один или несколько физических складов;
2. создать товары, указав единицу измерения, розничную и оптовую цены;
3. через «Начальный остаток / корректировка» внести фактические остатки на склады;
4. создать место хранения типа «Торговый представитель»;
5. создать пользователя с ролью торгового представителя и привязать его к этому виртуальному складу;
6. провести «Выдачу представителю» с физического склада на виртуальный склад представителя;
7. представитель входит в Android-приложение и видит склады, собственный остаток и две цены;
8. продажи уменьшают его товарный остаток и увеличивают задолженность;
9. сдача денег уменьшает задолженность;
10. возврат переносит товар с виртуального склада представителя обратно на физический склад.

## Android

Проект находится в `android/` и открывается обычным способом в Android Studio.

Для Android Emulator backend по умолчанию доступен как `http://10.0.2.2:8000/` — этот адрес уже задан в `BuildConfig`.

Для реального телефона необходимо заменить `API_BASE_URL` на адрес backend, доступный телефону по сети, и использовать HTTPS для рабочего развертывания.

В Android уже доступны:

- авторизация;
- остатки физических складов;
- собственный остаток представителя;
- розничная и оптовая цена;
- оформление продажи;
- возврат товара на выбранный склад;
- сдача денежных средств;
- текущая задолженность;
- автоматическое обновление остатков после серверных событий.

## Интеграция с 1С

Справочники товаров и мест хранения имеют поле внешнего идентификатора 1С. Предлагаемая схема двустороннего идемпотентного обмена описана в `docs/INTEGRATION_1C.md`.

Промышленный модуль обмена выделен в отдельную задачу: он должен иметь сервисную авторизацию, журнал обмена, ключи идемпотентности и подтверждение синхронизации документов.

## Технологический стек

- Backend: Python 3.12, FastAPI, SQLAlchemy 2, PostgreSQL, Pydantic;
- Real-time: WebSocket;
- Android: Kotlin, Jetpack Compose, Retrofit/OkHttp;
- Web: React + TypeScript + Vite;
- инфраструктура разработки: Docker Compose;
- CI: GitHub Actions для backend, web и Android.

## Важные ограничения текущей итерации

До промышленного запуска необходимо выполнить задачи по Alembic-миграциям, интеграционным тестам, аудиту операций и безопасному хранению Android-сессии/офлайн-очереди. Эти работы заведены отдельными задачами в GitHub.
