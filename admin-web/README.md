# Веб-панель «Цех»

Рабочее место администратора и руководителя на React + TypeScript.

## Реализовано

- JWT-вход через существующий FastAPI backend;
- отдельный доступ для ролей `admin` и `manager`;
- сводные показатели по складам, товарам, остаткам и задолженности;
- таблица складских остатков с розничной и оптовой ценой;
- каталог товаров;
- список торговых представителей, товар на руках и задолженность;
- браузерный real-time через короткоживущий одноразовый WebSocket-ticket;
- резервное REST-обновление раз в 60 секунд;
- для администратора: создание склада, товара и торгового представителя;
- для администратора: создание учетных записей `representative`, `manager` и `admin`;
- отдельный экран **Пользователи** со статусом доступа;
- отключение и повторное включение учетной записи администратором;
- установка временного пароля и немедленный отзыв ранее выданных JWT;
- защита от отключения собственной учетной записи текущего администратора;
- привязка, перепривязка и снятие учетной записи с торгового представителя;
- изменение розничной и оптовой цены существующего товара;
- для администратора: регистрация сдачи денег представителем;
- для администратора: приход товара на склад;
- для администратора: выдача товара торговому представителю;
- для администратора: перемещение товара между складами;
- журнал последних товарных документов для администратора и руководителя;
- безопасное сторнирование проведенного товарного документа администратором;
- денежный журнал и сторно ошибочного платежа;
- управленческие отчеты за период и по представителям;
- проверка доступного остатка и количества до отправки складской операции;
- серверная повторная проверка остатков и защита от конкурентного списания;
- `external_id` для идемпотентности каждой складской/денежной операции;
- адаптивная верстка для ноутбука, планшета и телефона.

## Локальный запуск

Сначала запустите backend из корня репозитория:

```bash
docker compose up
```

Затем:

```bash
cd admin-web
npm install
npm run dev
```

Панель будет доступна по адресу `http://localhost:5173`.

Vite проксирует запросы `/api` на `http://127.0.0.1:8000`, поэтому для локальной разработки не требуется отдельная настройка CORS.

## Сборка

```bash
npm run build
```

Результат создается в `admin-web/dist/`. В production статические файлы и `/api` обслуживаются через один Nginx/TLS-контур.

## Права

Руководитель получает режим просмотра: сводка, склады, каталог, представители, задолженность, товарный и денежный журналы и отчеты.

Администратор дополнительно получает разделы **Пользователи** и **Администрирование**, управление учетными записями и ценами, основные документы движения, сдачу денег и возможность сторнировать проведенные товарные и денежные операции.

Торговый представитель не может использовать эту панель: после входа роль `representative` отклоняется клиентом, а права на сами API-операции дополнительно проверяются backend.

## Управление доступом

Экран **Пользователи** доступен только администратору. На нем отображаются ФИО, email, роль и состояние учетной записи.

При отключении пользователя backend увеличивает `auth_version`, поэтому уже выданные access-token немедленно перестают приниматься. Повторное включение пользователя не восстанавливает старые токены — необходимо войти заново.

Установка нового временного пароля также увеличивает `auth_version` и отзывает все действующие токены пользователя. Если администратор меняет пароль собственной учетной записи, веб-панель очищает текущую сессию и переводит его на повторный вход.

Собственную активную учетную запись администратор отключить не может: защита действует и в интерфейсе, и на backend.

## Сторнирование

Сторно не удаляет исходный документ и его проводки. Документ получает статус `cancelled`, текущие остатки получают обратное движение, а для продажи создается компенсирующая денежная проводка.

Если обратное движение потребовало бы списать больше товара, чем сейчас есть у склада или представителя, backend отклоняет сторно с `409`. Это защищает цепочку учета: например, нельзя отменить приход, если часть этого товара уже была выдана и на складе недостаточно остатка для обратного списания.

## Безопасность

Access-token хранится в `sessionStorage`, а не в постоянном `localStorage`, и очищается при закрытии вкладки/сессии браузера. Production-контур работает только по HTTPS.

Основной JWT не передается в URL WebSocket: браузер получает отдельный короткоживущий одноразовый ticket и использует его только для подключения real-time канала.

Складская форма показывает текущий доступный остаток для удобства пользователя, но окончательная проверка выполняется backend внутри транзакции. Поэтому параллельная работа нескольких администраторов не может привести к корректному списанию одного и того же остатка дважды.
