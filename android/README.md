# Android-клиент «Цех — склад»

Приложение торгового представителя на Kotlin + Jetpack Compose.

## Реализовано

- вход по email и паролю через JWT backend;
- хранение access-token в зашифрованном виде: AES-GCM, ключ хранится в Android Keystore;
- автоматическое восстановление сессии после перезапуска приложения;
- просмотр остатков по всем складам;
- отображение розничной и оптовой цены для каждой позиции;
- просмотр собственного остатка торгового представителя;
- просмотр текущей задолженности;
- оформление продажи из собственного остатка;
- выбор розничной или оптовой цены при продаже;
- расчет суммы продажи до проведения;
- возврат товара на выбранный склад;
- история собственных товарных операций: получение товара, продажи, возвраты и сторнированные документы;
- локальная офлайн-очередь продаж и возвратов на Room3;
- автоматическая отправка очереди через WorkManager после восстановления сети;
- отдельное состояние операций, отклоненных сервером, с ручным повтором;
- идемпотентность повторной отправки продажи и возврата через `external_id`;
- защищенное WebSocket-соединение с backend;
- автоматическое обновление экрана при изменении остатков, цен, задолженности или истории операций;
- отдельный GitHub Actions workflow для сборки debug APK.

## Запуск

1. Запустить backend из корня репозитория:

```bash
docker compose up
```

2. Открыть каталог `android/` в Android Studio.
3. Дождаться Gradle Sync.
4. Запустить приложение на Android Emulator.

Debug-сборка по умолчанию обращается к backend по адресу:

```text
http://10.0.2.2:8000/
```

`10.0.2.2` — специальный адрес Android Emulator для доступа к `localhost` компьютера разработчика.

Для физического устройства необходимо заменить `API_BASE_URL` в `android/app/build.gradle.kts` на адрес backend, доступный устройству по сети. Для боевой сборки необходимо использовать HTTPS.

## Продажа и возврат

В разделе «Мой товар» доступны кнопки **Продажа** и **Возврат**. Перед отправкой приложение проверяет выбранное количество по последнему полученному остатку. Сервер выполняет окончательную конкурентно-безопасную проверку.

Для каждой версии формы создается уникальный `external_id`. Если ответ сервера потерян, повторная отправка этого же идентификатора не создает второе движение.

## Офлайн-очередь

Если отправка продажи или возврата не удалась из-за отсутствия сети, таймаута, HTTP 408/429 или временной ошибки backend 5xx, операция сохраняется в локальной Room3-базе вместе с исходным JSON и тем же `external_id`.

WorkManager ставит задачу с ограничением `NetworkType.CONNECTED`. После появления сети операции отправляются в порядке создания. Успешно подтвержденная операция удаляется из очереди.

HTTP 4xx, означающие постоянный отказ сервера, не повторяются бесконечно: запись переводится в состояние «требует проверки». Пользователь видит счетчик и может повторно поставить такие записи в очередь после обновления остатков.

Локальная очередь не уменьшает товар и не меняет задолженность оптимистично. Пока backend не подтвердил операцию, серверные остатки остаются источником истины. Это исключает расхождение при конфликте или отказе операции.

Выход из учетной записи не удаляет очередь. Без действующего JWT WorkManager не отправляет сохраненные операции; после следующего входа синхронизация планируется снова.

## История операций

Android получает историю через защищенный `GET /api/v1/my/documents`. Маршрут доступен только роли `representative` и выбирает документы по товарным проводкам представителя, привязанного к текущей учетной записи. Чужие документы в ответ не попадают.

В истории отображаются последние операции, их статус, товар, артикул, движение количества и сумма продажи. Сторнированные документы остаются видимыми как часть неизменяемой истории учета.

История загружается вместе с дашбордом и автоматически обновляется по существующему WebSocket-событию `state_changed` после продаж, возвратов и административного сторно.

## Денежное округление

Backend и Android используют округление денежных сумм до копеек по правилу `ROUND_HALF_UP`. Это особенно важно для весовых товаров, когда количество имеет до трех знаков после запятой.

## Безопасность локального HTTP

Основной Android-манифест не включает разрешение cleartext-трафика. `android:usesCleartextTraffic="true"` находится только в `src/debug/AndroidManifest.xml`, чтобы эмулятор мог работать с локальным HTTP backend.
