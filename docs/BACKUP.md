# Резервное копирование и восстановление

## Что резервируется

Основным источником данных является PostgreSQL. В нем находятся справочники, остатки, документы движений, денежный регистр, аудит и журнал обмена с 1С.

## Создание копии

Из корня проекта:

```bash
./scripts/backup.sh
```

Файл в custom-формате PostgreSQL создается в каталоге `backups/`.

Для рабочего сервера рекомендуется запускать резервирование внешним планировщиком не реже одного раза в сутки и дополнительно перед обновлением приложения/миграцией БД. Каталог `backups/` не должен быть единственным местом хранения копий: рабочие копии необходимо переносить на отдельный сервер или объектное хранилище с ограниченным доступом.

## Проверка копий

Наличие файла недостаточно. Периодически выполняйте тестовое восстановление на отдельной БД/сервере и проверяйте:

- вход администратора;
- количество складов и товаров;
- текущие остатки;
- задолженности представителей;
- последние товарные и денежные операции;
- журнал 1С.

## Восстановление

> Команда очищает текущие таблицы и заменяет данные содержимым резервной копии. Перед запуском убедитесь, что выбран правильный файл.

```bash
./scripts/restore.sh backups/ceh_sklad_YYYYMMDD_HHMMSS.dump
```

Скрипт останавливает backend, выполняет `pg_restore --clean --if-exists`, затем снова запускает backend. При запуске backend выполняется `alembic upgrade head`, поэтому старая корректная копия будет доведена до текущей версии схемы.

## Перед промышленным запуском

Рекомендуется дополнительно настроить:

1. автоматическую ежедневную копию;
2. ротацию копий, например 7 ежедневных + 4 недельных + 6 месячных;
3. шифрование копий вне сервера;
4. отдельные учетные данные/доступ к месту хранения;
5. мониторинг успешности задания;
6. регулярную учебную процедуру восстановления.
