# Интеграция с 1С

## Общий принцип

Интеграция проектируется как двусторонняя, идемпотентная и журналируемая. Для справочников и документов предусмотрены поля `external_1c_id` / внешний идентификатор документа.

## Предлагаемый обмен

### Из 1С в систему

- номенклатура;
- единицы измерения;
- розничные и оптовые цены;
- склады;
- начальные остатки или инвентаризация;
- статусы/блокировки номенклатуры.

### Из системы в 1С

- перемещения склад → склад;
- выдача склад → торговый представитель;
- возврат представитель → склад;
- продажи торгового представителя;
- сдача денежных средств;
- корректировки после согласования.

## Транспорт

Для первой версии рекомендуется HTTP JSON API поверх HTTPS. Со стороны 1С может использоваться HTTP-сервис/регламентное задание. Для больших объемов добавляется пакетный обмен.

## Идемпотентность

Каждый импортируемый документ должен иметь уникальный `external_1c_id`. Повторная отправка того же идентификатора не создает второй документ.

## Конфликты

После запуска промышленного обмена необходимо определить владельца каждого типа данных. Рекомендуемая схема:

- номенклатура и базовые цены — владелец 1С;
- оперативные движения представителей — владелец `ceh-sklad` до подтверждения экспорта;
- после успешной выгрузки документ получает отметку синхронизации и идентификатор документа 1С.

## Следующий технический шаг

Добавить `/api/v1/integration/1c/*` с отдельной сервисной авторизацией, журналом обмена, ключом идемпотентности и повторными попытками доставки.
