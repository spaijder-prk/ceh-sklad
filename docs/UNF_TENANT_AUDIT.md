# Аудит tenant mapping 1С:УНФ

Перед любым сетевым UAT bridge можно локально проверить, что mapping содержит все обязательные сопоставления:

```bash
ceh-unf-tenant-audit --mapping /etc/ceh-sklad/unf-tenant.json
```

Команда **не подключается ни к ceh-sklad, ни к 1С** и не читает секреты. Она проверяет:

- базовую структуру `TenantMapping`;
- `product_fields` для импорта номенклатуры;
- `location_fields` и непустой `location_allowlist`;
- наличие хотя бы одного обычного склада и одного склада представителя;
- два вида цен;
- организацию, покупателей розницы/опта, кассу и статью ДДС;
- все пять `payload_schemas`;
- обязательные semantic aliases шапки и табличных частей;
- `representative_payer_refs` для каждого allow-list склада представителя.

Успешный результат — JSON со `status=ready` и код процесса `0`. Если mapping неполон, возвращается `status=blocked`, список `errors` и код `3`.

`post_documents=false` считается допустимым для раннего UAT и отображается как предупреждение: документы будут записываться без автоматического проведения.

После локального аудита всё равно обязательна сетевая проверка через `ceh-unf-fresh-probe --details` / `ceh-unf-fresh-health`, потому что только реальный `$metadata` подтверждает фактические EntitySet и имена полей конкретного tenant.
