# Предметная модель складского учета

## Принцип учета

Остатки не меняются напрямую. Каждая операция создает документ и одну или несколько товарных проводок. Остаток — это сумма проводок по товару и владельцу остатка.

Положительная проводка увеличивает остаток, отрицательная уменьшает.

## Владельцы товара

В первой версии товар может находиться:

- на складе;
- у торгового представителя.

Одна товарная проводка относится ровно к одному владельцу: либо к складу, либо к торговому представителю.

## Документы

Поддерживаются следующие типы документов:

- `receipt` — приход товара на склад;
- `issue_to_representative` — выдача товара со склада торговому представителю;
- `representative_return` — возврат товара от представителя на склад;
- `warehouse_transfer` — перемещение между складами;
- `sale` — продажа товара торговым представителем;
- `adjustment` — резерв для будущих корректировок.

## Продажа

При продаже:

1. создается отрицательная товарная проводка по остатку представителя;
2. цена фиксируется в проводке на момент продажи;
3. цена выбирается из розничной или оптовой цены товара;
4. в денежном регистре создается положительная проводка на сумму продажи — задолженность представителя перед компанией увеличивается.

## Сдача денег

Сдача денег создает отрицательную денежную проводку. Итоговая задолженность представителя определяется суммой всех денежных проводок.

## Идемпотентность и интеграция с 1С

Для документов и денежных операций предусмотрено поле `external_id`. При повторной отправке операции с тем же `external_id` API возвращает уже созданную операцию вместо повторного списания. Это станет основой безопасного обмена с 1С.

## Ограничения текущего этапа

На текущем этапе еще не реализованы:

- авторизация и проверка ролей;
- отмена/сторнирование документов;
- WebSocket-уведомления об изменении остатков;
- Alembic-миграции;
- защита от конкурентного списания одного остатка несколькими запросами;
- Android-клиент и веб-панель.

Следующий серверный этап — добавить аутентификацию, миграции и конкурентно-безопасный регистр текущих остатков, сохранив журнал проводок источником истории.
